A · Stop and continue

1A stopped process is paused, not gone. The kernel keeps its whole record.

Every process is a record inside the kernel. Stopping it changes one field, the state, and takes it off the list of processes that get CPU time. Everything else stays: memory, open files, PID, the next instruction.

ps prints the state letter in its STAT column: R running, S sleeping (waiting for something), T stopped. A process is gone only after it exits and its parent collects its exit code.

2Your toy test: the process lived 1302 s and trained for about 11 s.

This is the run from your terminal. Each Ctrl+Z sent SIGSTOP, each fg sent SIGCONT, and the step counter never reset. zsh printed suspended because the kernel told it, the parent, that its child stopped.

22 steps × 0.5 s = 11 s of training 1302.175 s − 11 s ≈ 1291 s ≈ 21.5 min stopped, with nothing lost
The bars are not to scale. Ctrl+C sent SIGINT, which Python turns into KeyboardInterrupt, so that one ended the process.

3Inside the kernel, SIGSTOP freezes the process and SIGCONT unfreezes it on the spot.

The sender never touches the target directly. It asks the kernel, which marks the signal, makes the target act on it, and reports the result to the parent.

// Go, in the Supervisor syscall.Kill(4123, syscall.SIGSTOP) // step 1 syscall.Wait4(4123, &status, syscall.WUNTRACED, nil) // step 5 status.Stopped() // true: stopped by SIGSTOP syscall.Kill(4123, syscall.SIGCONT) // step 6
Nothing can catch, block, or ignore SIGSTOP in an ordinary process. SIGCONT resumes the process the moment the kernel receives it, before any handler runs. Without WUNTRACED, Wait4 returns only when the child exits.

4In Hibernus, the training hook closes the connection and waits. The Supervisor sends the stop.

The training hook can't stop itself (panel 11 shows why), so it gives the Supervisor a sign instead: it closes the connection. The Supervisor sends SIGSTOP from outside, confirms the stop, and runs CRIU.

# training hook, after step 5 (replaces today's wait) woke = threading.Event() # SIGCONT now sets a flag signal.signal(signal.SIGCONT, lambda signum, frame: woke.set()) self._sock.close() # step 6: no connection in the snapshot woke.wait() # sleeps; SIGSTOP freezes it here self._reconnect(step) # first line to run on the restore host
Why a flag and not signal.pause(): if SIGSTOP and SIGCONT both arrived before the wait began, pause() would sleep forever. The flag remembers that SIGCONT came. Having a handler also lets SIGCONT reach a PID 1 (panel 11). CRIU test Today's wait is python/hibernus/__init__.py:83.
B · Subreaper

5When a parent exits first, the kernel hands its orphan to PID 1.

Every process must have a parent. This is the demo you can run on your Mac: sh -c 'sleep 300 &'. The sh exits right away, and launchd (PID 1) adopts sleep.

On Ubuntu, PID 1 is systemd. PIDs 700, 812, and 813 are examples. Check the real one with ps -o pid,ppid,command -p <PID>.

6A subreaper catches the orphan before PID 1 does.

On the restore host, the Supervisor declares itself a subreaper. When CRIU exits, the kernel walks up from the dead parent and gives the training process to the first living subreaper it finds.

// Go, once, when the Supervisor starts (Linux only) unix.Prctl(unix.PR_SET_CHILD_SUBREAPER, 1, 0, 0, 0)
Docker and containerd use the same call to keep the processes they start. CRIU test confirms the hand-off with a CRIU-restored process.

7Detached CRIU exits right after the restore, and that exit creates the orphan.

Both modes restore the same way. The difference is what CRIU does next. Attached, it stays as the parent for the whole run. Detached, it reports success and leaves, so the subreaper can adopt the training process.

Detached is the flag criu restore --restore-detached. Its exit code means "the restore worked," which hib restore needs to decide whether to fall back to the application checkpoint.
C · PID namespaces

8One process, one number per namespace.

A PID namespace is a private PID counter. The kernel numbers a process in its own namespace and in every namespace above it, and keeps all the numbers.

// Go, in hib run: start the training process in a new PID namespace cmd.SysProcAttr = &syscall.SysProcAttr{Cloneflags: syscall.CLONE_NEWPID}
The training process is still the Supervisor's direct child. Only its numbering is private.

9Every PID call gets its answer from the asking process's namespace.

The same process is 4123 to the Supervisor and 1 to itself. Processes inside can't see out. Processes outside see everything inside.

Inside the namespace, /proc still lists host PIDs until something mounts it again. CRIU test checks whether PyTorch or CRIU care.

10The inside PID must match after a restore. The host PID never has to.

CRIU can't renumber a process. Without a namespace, it needs the exact host PID free on the restore host. With one, it needs PID 1 in a brand-new, empty namespace, which is always free.

// "PID 1 in the new namespace, any free PID on the host" clone3(flags = CLONE_NEWPID, set_tid = [1]) result: inside PID 1, host PID 5870
This only works if hib run started the training process in a namespace on the checkpoint host too. A process can't move into a new PID namespace after it starts.

11A namespace's PID 1 ignores signals it has no handler for, unless they come from outside.

The kernel protects every PID 1 so it doesn't die by accident. A training process that is PID 1 can't stop itself. Its own SIGSTOP comes from inside, so the kernel drops it. The Supervisor's comes from outside, so it gets through.
